# 决策 0001：平台代码与被测服务分两个仓库

状态：已采纳

## 背景

RegScope 需要分析真实的后端项目。
一开始的做法是在 RegScope 目录内建一个 `fastapi-pytest-demo`，而该目录自身也是一个 Git 仓库。

## 问题

1. 平台代码与被测代码混在同一目录，V1 采集 per-test coverage 时难以区分哪些文件属于被测服务、哪些属于平台本身。
2. Git 仓库嵌套：外层仓库执行 `git add -A` 时容易把被测服务整体纳入平台仓库。
3. V2 要在被测服务上取两个 commit 做 diff。两套代码同一仓库时，平台的每次改动都会进入同一个历史，干扰实验。

## 决定

平台仓库与被测服务仓库分开，各自独立，互不包含。

```text
F:\大学\大三上\
├── RegScope\        平台仓库：分析逻辑与文档
└── order-service\   被测服务仓库：分层订单系统
```

RegScope 不假定被测服务的位置，通过路径参数指向目标仓库。

## 需要接受的影响

1. RegScope 无法直接 `import` 被测服务的模块，运行测试与采集覆盖必须通过子进程调用 pytest 与 coverage。
2. 平台仓库的 Git 历史只包含平台自身的改动，实验结果与被测服务的历史一一对应。
3. 被测服务可以被替换。以后接入 FastAPI 官方模板或其他开源项目时，只需给出路径，平台结构不动。
